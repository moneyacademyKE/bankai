# Working with bankai

bankai is the task-memory mesh for this project. Tasks are content-addressed
(SHA-256); IDs are short hash prefixes (bk-XXXX), with hierarchical subtask
IDs of the form bk-XXXX.N.

## Workflow
1. `bankai ready` — list unblocked tasks; pick one.
2. `bankai update <id> --claim` — claim it (sets in_progress + assignee).
3. Do the work; commit atomically per logical change.
4. `bankai update <id> completed` — mark done.
5. `bankai dep add <id> <target> [--type blocks]` — wire a dependency (cycle-safe).
6. `bankai create <title> [--label L].. [--parent <id>] [--priority N]` — new task/subtask.
7. `bankai remember "insight"` — persist a durable note for future runs.
8. `bankai compact` — retire closed tasks (keeps `prime` bounded).
9. `bankai prime` — re-read this workflow + recent memories.

All command output is JSON: {"ok": ...} / {"error": ...}. A `closed` task
(won't-do) does NOT satisfy a dependency — only `completed` does.
